# 多 Agent 研究：分工要有边界

主题：多 Agent 协作

编辑版：1.1 · 2026-10-16

来源：https://www.anthropic.com/engineering/multi-agent-research-system

## 先抓住这个问题

一项研究包含需求、资料可得性和风险三个方向。让一个助手顺序调查可能较慢，让三个助手同时调查又可能产生重复报告和冲突结论。拆分之前，需要确定哪些工作真正独立，以及汇总时怎样保留证据和处理分歧。

## 理解方法

将可以独立调查的方向分开，给出清楚的目标与交付格式，再由协调方综合证据、处理冲突。

## 适用边界

并行会增加成本和协调负担。高度依赖共享状态的任务，不应因为可以开更多 Agent 就全部拆开。

## 换个场景想想

【原创演练】调查“内部知识助手是否值得部署”。分别安排使用需求、数据可得性、风险约束三条调查线；每条都提交事实、来源、缺口，最后由一人合并，避免各写一篇互不相干的报告。

## 把它带回自己的工作

选一个你正在做的小任务，写下能借鉴的一点、暂不适用的一点，以及验证效果需要观察的证据。案例与练习均为本学习库原创，用于迁移理解，不代表来源文章的实验结果。

## 可选回想

2. 这项调查怎样划分独立任务，怎样避免最后得到三份重复报告？

3. 这篇方法有什么适用边界？你会怎样检查它在自己的任务中是否有效？

## 对照要点

1. 文章介绍主 Agent 协调多个研究 Agent 的系统，讨论并行探索、信息汇总和可靠性挑战。将可以独立调查的方向分开，给出清楚的目标与交付格式，再由协调方综合证据、处理冲突。

2. 按问题边界分工，统一证据格式与返回要求，规定冲突处理和总预算。说明哪些决策必须集中。

3. 并行会增加成本和协调负担。高度依赖共享状态的任务，不应因为可以开更多 Agent 就全部拆开。
