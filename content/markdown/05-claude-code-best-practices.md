# 把编码任务变成可验证的小步

主题：长任务执行与交接

编辑版：1.1 · 2026-10-16

来源：https://www.anthropic.com/engineering/claude-code-best-practices

## 先抓住这个问题

一句“把搜索修好”没有说明哪里出错，也没有说明怎样才算修好。助手可能改了很多代码，却没有触及用户遇到的问题。开始编码前，怎样把模糊诉求变成可以复现、范围清楚、能够验证的小任务？

## 理解方法

给出明确目标、相关上下文和验证方式；先调查，再安排改动，最后用实际检查确认结果。

## 适用边界

工具命令与产品设置会变化。本导读讲工作方法，执行前应核对当前文档，不能把旧日期当成现行功能说明。

## 换个场景想想

【原创演练】将“修好搜索”改写为任务说明：指定复现场景、期望结果、相关范围，以及如何证明修复有效。再删去与问题无关的重构要求。

## 把它带回自己的工作

选一个你正在做的小任务，写下能借鉴的一点、暂不适用的一点，以及验证效果需要观察的证据。案例与练习均为本学习库原创，用于迁移理解，不代表来源文章的实验结果。
