# 让数据处理留在执行层

主题：工具设计、MCP 与 Skills

编辑版：1.1 · 2026-10-16

来源：https://www.anthropic.com/engineering/code-execution-with-mcp

## 先抓住这个问题

为了找出一千条记录中缺少日期的条目，助手把全部数据先读进对话，再把它们重新写给另一个工具。确定的数据处理为何要反复经过模型？哪些计算可以留在执行环境中，哪些结果才值得进入上下文？

## 理解方法

按需发现工具，让确定的数据转换和批量处理在执行环境中完成，仅把有用结果交给模型。

## 适用边界

减少上下文流转不等于自动获得安全性。执行代码仍需权限边界、错误处理和结果核验。

## 换个场景想想

【原创演练】读取一千条文档元信息，只需找到缺失日期的记录。先在执行层筛选和统计，再向模型返回异常项及总量，避免把所有记录反复复制进对话。

## 把它带回自己的工作

选一个你正在做的小任务，写下能借鉴的一点、暂不适用的一点，以及验证效果需要观察的证据。案例与练习均为本学习库原创，用于迁移理解，不代表来源文章的实验结果。

## 可选回想

1. 暂时合上导读：用自己的话说明这篇文章要解决什么问题，以及它的主要方法。

2. 上述任务哪些步骤适合代码，哪些需要模型判断？

3. 这篇方法有什么适用边界？你会怎样检查它在自己的任务中是否有效？

## 对照要点

1. 文章讨论工具定义和中间结果占用上下文的问题，并用代码组织 MCP 调用及数据处理。按需发现工具，让确定的数据转换和批量处理在执行环境中完成，仅把有用结果交给模型。

2. 筛选、计数和去重可确定执行；含义判断再交模型。保留可追溯记录，避免用摘要隐藏处理错误。

3. 减少上下文流转不等于自动获得安全性。执行代码仍需权限边界、错误处理和结果核验。
