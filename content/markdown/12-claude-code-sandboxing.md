# 用执行边界减少重复审批

主题：权限、安全与隔离

编辑版：1.1 · 2026-10-16

来源：https://www.anthropic.com/engineering/claude-code-sandboxing

## 先抓住这个问题

你告诉助手只修改输出目录，它却拥有整个工作区的写权限。此时安全边界主要依赖它每一次都理解并遵守提醒。哪些限制应直接落实到文件和网络访问能力，哪些判断仍需要结合用户意图？

## 理解方法

将允许访问的资源落实到执行环境，而不只依赖自然语言提醒或每次点击确认。

## 适用边界

沙箱有边界，也有配置和兼容成本。允许访问的范围内仍可能出现错误，需要结合任务约束。

## 换个场景想想

【原创演练】为资料助手列出资源表：可写的输出目录、只读资料目录、允许连接的域名。假设工具尝试写入其他目录，明确由什么机制拒绝，而不是要求它“自觉遵守”。

## 对照要点

1. 文章讨论通过沙箱限制文件与网络访问，为编码 Agent 提供更清楚的执行范围。将允许访问的资源落实到执行环境，而不只依赖自然语言提醒或每次点击确认。

2. 指令约束行为，权限限制实际能力。两者应配合，并测试越界动作是否确实被拒绝。
