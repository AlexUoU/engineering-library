# 先选最简单的方案：从工作流到 Agent

主题：Agent 基础与架构选择

编辑版：1.1 · 2026-10-16

来源：https://www.anthropic.com/engineering/building-effective-agents

## 先抓住这个问题

做一个资料助手时，应该把步骤提前写好，还是让模型自行决定下一步？如果只是固定格式的周报归档，引入自主规划可能徒增复杂度；如果需要根据新证据不断调整调查方向，固定流程又可能不够用。先辨认任务中的不确定性，才能选择合适的实现方式。

## 理解方法

先判断步骤能否预先确定，再决定是否需要动态规划。检索、工具和记忆可以增强模型，但复杂度应由实际任务推动。

## 适用边界

灵活性会带来额外成本和不确定性。开放式任务也需要明确完成条件，不能把自由行动等同于无限循环。

## 换个场景想想

【原创演练】你要做一个资料助手：一种请求只把固定格式周报归档，另一种请求需要调查互相矛盾的资料。先分别写出可预知的步骤，再圈出必须根据发现改变方向的环节。两类请求不必共用同一种架构。

## 把它带回自己的工作

选一个你正在做的小任务，写下能借鉴的一点、暂不适用的一点，以及验证效果需要观察的证据。案例与练习均为本学习库原创，用于迁移理解，不代表来源文章的实验结果。

## 对照要点

1. 文章区分预先安排路径的工作流与由模型动态决定行动的 Agent，并建议从简单方案起步。先判断步骤能否预先确定，再决定是否需要动态规划。检索、工具和记忆可以增强模型，但复杂度应由实际任务推动。

2. 归档优先考虑确定流程；调查才可能需要动态行动。说明理由、工具边界与完成条件，而不只给架构命名。

3. 灵活性会带来额外成本和不确定性。开放式任务也需要明确完成条件，不能把自由行动等同于无限循环。
